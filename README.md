# EXIT POPUP

**ライセンスはディレクトリで分かれています**: `packages/embed/` = **MIT** / それ以外 = **AGPL-3.0**。
詳細は **[LICENSING.md](./LICENSING.md)**(ルートの `LICENSE` は AGPL-3.0 の全文だけを置いています)。

**LP に `<script>` を1行貼るだけで、離脱しかけた訪問者にポップを出す**ツール。

いま LP から出ていく人はそのまま消えるだけで、再訪も再提案もできない。EXIT POPUP を入れると
**離脱の瞬間に「もう1回だけ提案する枠」**が生まれ、**その枠の効き目(表示・クリック・トリガ別)が
数字で見える**ようになる。

> 土台は **Cloudflare(Workers + D1 + R2)** です。自分の Cloudflare アカウントに立てる手順は
> **[docs/deploy.md](./docs/deploy.md)** にあります。

## ライセンス(ディレクトリで分かれている)

| 場所 | ライセンス |
|---|---|
| `packages/embed/`(npm 名 `exit-popup-js`。他人の LP に読み込まれる側) | **MIT** |
| それ以外すべて(サーバー・管理画面) | **AGPL-3.0** |

理由と、分割を機械で効かせている場所は **[LICENSING.md](./LICENSING.md)** に書いてあります。

## v1 の範囲

| 入れる | 入れない |
|---|---|
| 埋め込みタグ(`<script>` 1行)+ 配信エンドポイント | 入力フォーム / リード獲得(**個人情報を1件も集めない**) |
| 離脱トリガ3種(exit intent・スクロール・滞在。実装済み) | AI の自由回答チャット |
| ポップの型2種(テキスト+ボタン / 画像・GIF) | 任意 HTML・CSS・JS の入力(XSS の入口を作らない) |
| 頻度制御(N日出さない / セッション内1回) | ASP パラメータの引き継ぎ |
| パターン(最大5)ごとの数値(表示・クリック・閉じる・トリガ別・端末別) | A/B の割り当て・自動勝者選定(下の「現在の制限」) |
| 管理画面(単一管理者) | 複数ユーザー・チーム権限 |
| | 課金・ホスティング版 |
| | チャットボット型のポップ |

⚠ **成約(ASP)の数字は取りません。** ASP 側にあり、こちらからは観測できないためです。

## いまできること

- ライセンスの分割(MIT / AGPL-3.0)と、それを守る CI の検査
- 管理画面で、キャンペーン(ポップ)の名前・パターンカード(最大5)・表示設定(出すきっかけと頻度)・
  タグの設置(埋め込みタグと許可ドメイン)・WORKSPACE 名を扱える
- **データモデル**(所有者 / サイト / 許可ドメイン / ポップ / トリガ設定 / パターン / チャットボットのノード / イベント)
  —— **Cloudflare D1**(`db/migrations/`)
- **配信の Worker**(`src/delivery/worker.ts`・設定は `wrangler.delivery.jsonc`)
  - `GET /api/v1/config` —— サイトキー + `Origin` から、いま有効なポップの設定を返す
  - `POST /api/v1/events` —— 発火・抑制・表示・クリック・閉じるを受ける
  - `/embed/*` —— 埋め込みスクリプト(静的配信)
- **管理画面の Worker の API**(`src/admin/app.ts`・設定は `wrangler.admin.jsonc`。Hono)
  - ログイン(管理者1人・パスワードは `npm run admin:hash` が乱数で作る)・セッション・ログアウト
  - サイト・ポップ・パターン・トリガ・頻度の作成・更新・アーカイブ・削除
  - 画像のアップロード(本文は画像のバイト列そのもの・3MB で打ち切り・中身で形式を判定・長い辺 2,400px まで・JPEG の Exif を落とす)
  - ⚠ 画像は **Cloudflare のアカウントで R2 が有効になっていること**が前提です(バケット `adpop-images` を作る)
- **管理画面の画面**(`src/app/*`。Next の静的書き出し `out/` を、管理画面の Worker の `assets`
  が `/api/*` 以外の URL で静的配信する。`run_worker_first: ["/api/*"]`)
  - ログイン・ダッシュボード・デザイン(ポップ一覧とパターン編集)・表示設定・タグの設置
    (埋め込みタグ・許可ドメイン)・アーカイブ・完全削除の確認
  - 表示/クリック/閉じたの数値(`GET /sites/:siteId/popups/stats`)を一覧(直近7日)・アーカイブ済み
    /完全削除の確認(累計)に表示する。取得できなかった(通信失敗・500・503)ときは **"—"** のまま
    (0件と誤読させない)
  - 画像の代替テキスト(`imageAlt`)は入力欄から保存され、必須判定(ボタン文言が空のときだけ必須)は
    `src/lib/data/shapes.ts` の `requiresImageAlt` と同じ条件を画面側でも使う
  - 🔴 稼働中のポップから「配信できる最後のパターン」を奪う操作(アーカイブ・画像を外す・編集で画像無しの
    画像型にする)は 409(`last_deliverable_variant`)で断られる。サーバーが返す文言
    (「稼働中のポップには、配信できるパターンが1つ以上必要です。先に停止してください」)をそのまま出す
  - ポップ編集で未保存の変更がある間、パンくず・ログアウトは確認モーダル(既存の `Modal`/
    `ConfirmDeleteDialog` と同じ部品)を経由する。ブラウザを閉じる・再読み込みは `beforeunload`
    (ブラウザ自身の確認。文言はカスタマイズできない)
  - **CSP(`out/_headers`)**: `next build` 後に `scripts/build-admin-headers.mjs` が実物の HTML から
    インラインscriptのハッシュを数えて `script-src` に列挙する(手で書き写さない)。
    `unsafe-inline`/`unsafe-eval`/ワイルドカードは使わない
- **配信の Worker の `/img/<キー>`** —— パターンの画像を R2 のバインドから返す(バケットは公開しない)
- **管理画面が使うデータ層**(`src/lib/data/admin.ts` / `auth.ts` / `images.ts`)
- **埋め込みスクリプト**(タグ1本 → 設定取得 → 離脱の検知 → ポップの表示)

### D1 に移して弱くなった守り(代償)

- 🔴 **DB が最後の砦ではなくなりました。** 所有者の分離はデータ層のコードが持つので、
  **その誤り1つで他人の行に届きます**(RLS を持つ DB なら、そちらが止めます)。検査は全関数を撃ちますが、
  **所有者の分離を実際に守っているのは、データ層の関数(読み取り・更新・削除の所有者の条件)と D1 のトリガ・外部キー**です。
  境界の検査(D1 に触るのはデータ層だけ)は**補助で、網羅ではありません**: `any` に落とした値(`(env as any).DB`)は見えず、
  リポジトリの中の静的な検査は、編集できる人には必ず外せます。v1 は管理者1人です。
- 🔴 **REPLACE 系の守りは「一意なキーごとにトリガを置いた」ことに乗っています。** 一意なキーを足してトリガを
  足し忘れると、その表は REPLACE で行を入れ替えられます(検査が一意なキーの一覧を突き合わせるので、検査は落ちます)。
  データ層の SQL の字面の検査は、**組み立てた文字列**(`"re" + "place"`)を見ません。
- 🔴 **形の検査が DB に残るのは GLOB / LIKE で書ける範囲だけです**(SQLite に正規表現が無い)。
  `https://localhost` のようなドットの無いホストは、**DB を直接触られると**許可ドメインとして入ります
  (配信の口は入口で `isOrigin` を通すので、そこからは入りません)。
- 🔴 **Cloudflare の API トークンに D1 の権限があれば、全データを読み書きできます。**
  「専用ロールで届く範囲を関門で数える」に当たるものはありません。**トークンの範囲を絞るのは運用**です。
- ⚠ **本文 4KB の上限は Worker のコードの中(入口とデータ層)にしか無く、DB の側には置いていません**
  (PostgREST のように DB の関数を直接叩ける経路があれば DB にも置くべきですが、
  **D1 にはその経路がありません**)。
- ⚠ 同時実行: 上限の判定は「D1 は1つのデータベースのクエリを1つずつ処理する」
  (Cloudflare の D1 limits の文書)に乗っています。**2つの要求を本当に並べて撃つ検査はありません**
  (ローカルでは並びを保証できないため)。

### 1インストール = 1サイト

- v1 は OSS の1インストールにつき管理者1人なので、「サイトは所有者ごとに1つまで」という DB のトリガ
  (`sites_single`・`db/migrations/0006_sites_single_per_owner.sql`)が、実質「インストールに1サイト」になる。
  2つ目のサイトの作成は、管理画面からだけでなく **API を直接叩いても** 409(理由は上限超過と同じ `limit`/`sites`)で断られる。
- 🔴 **既存のデータは変えない・消さない。** このマイグレーションは追加だけ。新しく立てた環境では、当てても何も起きない。
- ⚠ **1つの所有者がすでに2サイト以上を持つ環境に当てた場合**: 既存のサイトは**そのまま残り**、
  その所有者はもう新しいサイトを作れなくなる(どちらの既存サイトを使うかの選択や、片方を消す処理は無い)。
  サイトを1つに絞りたい場合は、使わない方を管理画面(または API)の削除で手動で消すこと。

### 埋め込み方(いまの形)

```html
<script async src="https://<配信ホスト>/embed/t.js" data-exit-popup-site="<サイトキー>"></script>
```

- **配信ホストはタグの `src` から読みます。**コードに直書きしていないので、
  ドメインを変えたらタグを貼り替えるだけで移せます。
- ⚠ サイトキーは **HTML に出る公開値**です。秘密ではありません。守っているのは
  **許可ドメイン**(`site_allowed_origins`)で、**登録していない Origin には設定を返しません**。
- 🔴 **旧名・当面維持**: すでに貼ってあるタグ(`data-adpop-site` 属性・`/embed/adpop.js`・`?adpop_preview=1`)も**そのまま動きます**。
  新旧の両方が付いたときは、**新名が空でなければ新名が勝ちます**(空なら旧名)。新しく貼るときは新名(上のタグ)を使ってください。
- `?exit_popup_preview=1` を付けると**頻度制御を無視して出ます**。⚠ このときのイベントは**1件も送りません**。

### 現在の制限(未実装・意図して入れていないもの)

| 入れていないもの | 補足 |
|---|---|
| **トリガ: 戻る・無操作・タブ切替** | **実装しているのは exit intent(PC のみ)・スクロール・滞在の3種**です。管理画面の API は未実装の種類を 400 で断ります。サーバーが返す設定に未知の種類が混じっても、**埋め込みスクリプトは知らない種類を黙って無視します** |
| **A/B の割り当て** | パターンは最大5つ保存でき、重み(`weight`)は配信の応答に載りますが、**重みは使っていません**。出るのは配信できる**先頭のパターン**です。振り分けはしません |
| **CV 計測タグ(`conversion`)** | 投入エンドポイントは `conversion` を**受け付けません**(別の入口になるため)。データには「CV 後は出さない日数」の列がありますが、設定する画面も書き込む経路もありません |
| 🔴 **レート制限** | **入っていません。** イベント投入は `Origin` とサイトキーの確認と、本文 4KB の上限だけで守っています |
| **設定 JSON の CDN キャッシュ** | 応答が**サイトキー × Origin の認可の結果**なので、無効化の手順を決めるまで入れていません(いまは `no-store`) |
| **プレビュー(preflight)対応** | 埋め込みスクリプトは単純リクエストしか送らない(`text/plain`)ので preflight は起きません。`OPTIONS` は実装していません |

### ポップの見た目について

🔴 **いまの見た目は仮置きです。** 枠・閉じるボタン・見出し・本文・ボタンだけで、
**デザインは実寸のモックで決めてから**入れます。

## 動かし方(開発)

前提: Node.js 24。**Cloudflare のアカウントは要りません**(全部ローカルの wrangler / workerd で動きます)。

```bash
npm install
npm run lint
npm run typecheck
npm test                          # D1 の型紙を `wrangler d1 migrations apply --local` で作ってから走る
npm run check:bundle-size
npm run check:embed-independence
npm run build

# 先に deploy.local.json を作る(ローカル確認用の仮の値でよい。最小例は docs/deploy.md「ローカルで動かす」)
#   → 配信・管理画面とも、この設定から作った生成物で wrangler を動かします

# 配信の Worker をローカルで起動する
npm run delivery:migrate:local    # ローカルの D1 にスキーマを当てる(.wrangler/state)
npm run delivery:dev              # 埋め込みスクリプトを束ねてから wrangler dev(http://localhost:8787)

# 管理画面(API + 画面)をローカルで起動する
npm run admin:hash                # パスワードと秘密を作る(パスワードは1回だけ表示)
#   → 出力の値を .dev.vars に書く(ADMIN_PASSWORD_HASH / ADMIN_RATE_LIMIT_KEY / ADMIN_OWNER_ID / ADMIN_EMAIL)
npm run admin:migrate:local
npm run admin:dev                 # Next の静的書き出し(out/)を作ってから起動。http://localhost:8788 — /api/* 以外は out/ の静的配信
```

⚠ `npm run admin:dev` は `out/` をそのまま配る(Next の dev サーバーではない)。画面を直したら
`admin:dev` を再起動する(起動のたびに書き出し直す。ホットリロードは無い)。

ローカルの `admin:dev` は、配信元を `http://localhost:8787`(`delivery:dev` の待ち受け先)にして書き出します
(ポートを変えたら `ADPOP_LOCAL_DELIVERY_ORIGIN=http://localhost:<port>` を付けます。docs/deploy.md「ローカルで動かす」)。

埋め込みタグに出す配信ホストは `NEXT_PUBLIC_DELIVERY_ORIGIN`(ビルド時に埋め込まれる公開値。
`.env.example` 参照)。未設定だとサイトの画面に「(配信元のURLが未設定)」と出す(壊れた URL を
タグに出すより安全な既定)。

⚠ `npm test` が使う D1 は、**本番と同じ `wrangler d1 migrations apply`** で作った型紙の複写です
(`tests/setup/d1-template.ts`)。SQL を自前で文に分けて流すことはしていません。

## 外部送信する情報の一覧(電気通信事業法・外部送信規律)

**このタグが外部送信する情報**は次のとおりです(**そのまま転記できる形**で置いています)。

| 項目 | 内容 |
|---|---|
| **送信先** | タグの `src` に書いた配信ホスト(**自前ホストなら、その運営者自身のサーバー**) |
| **送信される情報** | 匿名ID(`localStorage` 由来の32桁の16進)/ **ページ URL(スキーム + ホスト + パスのみ)** / イベントの種類(発火・抑制・表示・クリック・閉じる)/ トリガ種別 / **端末種別(スマホ・PC の2値)** / 閉じ方(ボタン・背景・Esc)/ 発生時刻 / サイトキー・ポップとバリアントの公開用の識別子 |
| **送信されない情報** | **URL のクエリ文字列とフラグメント**(送る前にも、保存する前にも落とします)/ **EXIT POPUP の DB への IP アドレスの保存**(⚠ Cloudflare の側は「Cloudflare の側で保存されうるもの」の節)/ 生の User-Agent / サードパーティ Cookie / 入力フォームは持っていないので、訪問者が入力した値 |
| 🔴 **送信されうる情報(注意)** | **ページ URL のパスに氏名やメールアドレスが含まれている場合、それは送信されます。** EXIT POPUP が落とすのは**クエリ文字列とフラグメントだけ**で、パスは残します(`/thanks/taro@example.com` のような URL 設計をしている LP では、タグを貼る前に URL を見直してください)。⚠ ただし `user@host` の形(`https://taro@example.com/…`)は**保存を断ります** |
| **利用目的** | ポップの表示制御と効果測定 |
| **送信を止める方法** | タグを外すこと(⚠ オプトアウト UI はありません) |

⚠ 埋め込み先の運営者が規律の対象事業者に当たるかは、その人の事業内容で決まります。
**EXIT POPUP は「対象です / 対象外です」の判定をしません。**

## 管理画面のログインと守り

| 守り | 中身 |
|---|---|
| パスワード | **人が選ばない**。`npm run admin:hash` が 128 ビットの乱数で作る。保存はハッシュだけ(PBKDF2-SHA256・100,000 回・secret)。パスワード管理ツールへ保存するときの一致方式は [docs/deploy.md](./docs/deploy.md) §8 を見てください(ホスト完全一致に絞る・絞れないツールは目で確認する) |
| 試行回数 | 同じ接続元は 15 分に 5 回まで(**パスワードを確かめる前に数える**)。接続元は `CF-Connecting-IP` だけ・IPv6 は /64 に丸める。**IP は保存しない**(日付つきの HMAC)。⚠ **運用の前提**: 管理画面の Worker の前に、**同じゾーンの別の Worker を置かないこと**。同じゾーンの Worker から来たサブリクエストでは、接続元のヘッダを前段が書き換えられる(Cloudflare の HTTP ヘッダの文書の `x-real-ip` の記述で確認)= 接続元ごとの数が前段の値になる |
| セッション | Cookie は `__Host-adpop_session`・HttpOnly・Secure・SameSite=Strict。最長 7 日・操作が無ければ 24 時間。**パスワードを置き直すと全部ログアウト**。DB に保存するのは Cookie の値の SHA-256 |
| CSRF | GET/HEAD 以外は Origin の完全一致・`Sec-Fetch-Site`(在れば same-origin)・Content-Type(JSON / 画像は `application/octet-stream`)。CORS のヘッダは返さない |
| 所有者 | 所有者 id はセッションからだけ取る。他人の行・存在しない行は 404 |

🔴 **管理画面は、LP と別の登録ドメインに置くか、同じ登録ドメインの別サブドメイン + 下の条件で置いてください。**
`SameSite=Strict` は**同じサイト(登録ドメインが同じ)の別のオリジンには効きません**。LP に第三者のタグが
載っていると、同じサイトに他人のスクリプトがいることになり、そのときに守っているのは Origin の完全一致・
`Sec-Fetch-Site`・Content-Type の検査と、`__Host-` 接頭辞の Cookie(`Domain` 属性を持てない)です。
同じ登録ドメインの別サブドメインに置く場合は、次の条件を満たしてください:

1. **そのゾーンに zone の routes(パターンで受ける方式)を作らない。** Custom Domain(ホスト名の完全一致)
   だけにする。zone の route は Custom Domain の Worker より前に走る(Cloudflare 公式文書「Custom Domains」)ため、
   広い pattern の Worker が1つ増えるだけでログインの通信を横取りできる経路になる。
2. **管理画面の Cookie に `Domain` 属性を付けない。** `__Host-` 接頭辞(このリポジトリの既定)を使う。
3. 🔴 **管理画面の前に Cloudflare Access を必ず置く**(手順は [docs/deploy.md](./docs/deploy.md) §7)。
   同じ登録ドメインの別サブドメインに置く構成では、ログインの口がどこにあるかを名前で隠せない
   (証明書は Certificate Transparency ログで公開される)ため、Access を省略可能な任意の強化とは
   扱わない。⚠ Cloudflare の料金ページ([Zero Trust plans](https://www.cloudflare.com/plans/zero-trust-services/))は
   無料プランを案内しているが、具体的な無料の人数とカード登録の要否は確認できていない(未確認)。

🔴 **Cloudflare のアカウントを守ってください**: 二要素認証を必ず有効にし、デプロイに使う API トークンは
D1・R2・Workers に絞ってください。**アカウントが乗っ取られたら、管理画面も全部取られます**(secret を書き換えられる)。

⚠ **本番の Workers は PBKDF2 の反復を 100,000 回までに制限しています**(workerd のソースの既定の上限)。
手元の wrangler にはこの上限が無いので、**手元の検査では上限に当たっても気づけません**。
本番に出す前に、本番の Worker で1回ログインして確かめてください。

## 数字の読み方(先に断っておくこと)

## 既知の限界

- **頻度制御は埋め込み先ドメインの `localStorage`** に保存します。
  localStorage が使えない / 消される環境では**抑制が効きません**(Cookie にも第三者にも逃がしません)。
  ⚠ 記憶の単位は**サイトごと**です(表示設定=きっかけ・頻度がサイトごとに1組なのに合わせています)。
  **稼働中のポップを切り替えても、同じサイトでは抑制が引き継がれます。**
- 訪問者の識別は**匿名IDのみ**。**EXIT POPUP は IP アドレスを D1 に保存しません**。User-Agent は「スマホ / PC」の2値に落とします。
  ⚠ **Cloudflare の側で保存されうるもの**は下の節を見てください(EXIT POPUP の設定で切れるものと、切れない・確かめていないものがあります)。
  ⚠ **「氏名・メール・電話を送らない」とは言い切れません** —— それらが**ページ URL のパスに
  含まれていれば送信されます**(落とすのはクエリ文字列とフラグメントだけ)。上の表を見てください。
- **オプトアウト UI はありません**(止める方法はタグを外すこと)。
- 🔴 **イベント投入にレート制限がありません。**守っているのは `Origin` の照合と
  サイトキーの存在確認、本文 4KB の上限だけです。
- **戻るトリガは実装していません。**いまの埋め込みスクリプトは `history` に触りません。
- **匿名IDは、`crypto` が使えない環境では `Math.random` で作ります。**暗号的ではありません
  (頻度制御のための識別子で、秘密でも認証でもないため)。
- **端末の2値は `(pointer: coarse)`**、それが無ければ `navigator.maxTouchPoints` で決めます。
  ⚠ どちらも無い古い環境は「PC」と数えます。
  EXIT POPUP は、ページを開いた時点で**主な入力装置が指かどうか**(CSS の `(pointer: coarse)`。使えない環境では
  `navigator.maxTouchPoints`)を見て「スマホ」か「PC」かを**1回だけ**決めます。**画面の幅や User-Agent は
  使いません。**この結果は、**どちらの表示設定・デザインを使うか**と、計測イベントの「端末」の**両方**に
  使います。タブレットはスマホ側、タッチ画面つきのノート PC は PC 側に入ります。判定の結果はサーバーに
  「スマホ / PC」の2値だけが送られます。
  ⚠ **いまスマホで使える離脱トリガは2種(スクロール・滞在)です**。exit intent は PC 専用の仕組みなので、スマホでは使えません。
  スマホ用の表示設定でこの2種のどちらも ON にしていなければ、スマホでポップは1度も出ません。
- 🔴 **Origin の偽造は防げません。** ブラウザは本物の Origin を送るので、
  「他人が自分の LP にタグを貼った」場合は止まります。**curl に対しては何も守っていません。**
- 🔴 **Workers Free の「1日 10 万リクエスト」はアカウント全体の上限**です。管理画面のログインの口を連打されると、
  **配信も同じ枠を食います**(配信の口にもレート制限はありません)。WAF のレート制限の可否・料金は未確認です。
- 🔴 **D1 の無料枠の「1日 書き込み 10 万行」は、Workers の「1日 10 万リクエスト」より先に尽きます。**
  イベント1件の投入(`fire`)は表1行 + 索引4本で**約5行の書き込み**になる見込みなので、**偽造イベント約2万件**で
  無料の書き込み枠が尽きると見込まれます(一次: [D1 Pricing](https://developers.cloudflare.com/d1/platform/pricing/)
  「When your account hits the daily read and/or write limits, you will not be able to run queries against D1」。
  件数は索引の数え方からの**推定**、本番で計測していません)。尽きると**アカウントの D1 全体に問い合わせできなくなり**、
  配信(fail-closed。LP は無傷)と管理画面(ログインもできない)の両方が UTC 0 時まで止まります。
  **イベント投入にレート制限が無いこの v1 のままでは、他人の LP に配ると枯渇させられます。**
  自分の LP だけで試す最初の本番はこの限界を受け入れて出せますが、**他人の LP にタグを配る前にレート制限は必須です**。
- **画像**: JPEG の Exif(APP1)は落としますが、**PNG・WebP の撮影情報のチャンクは落としていません**。
  画像の寸法は**長い辺 2,400px まで**(超えたら断る)。寸法はファイルの先頭(ヘッダ)から読み、読めない画像も断ります。
- **画像を削除しても**、CDN とブラウザには最長 1 年キャッシュが残りえます(配信の `/img` は `immutable`)。
  **消す予定の画像のキーは、先に積みます**(`pending_image_deletions`。参照を外す・行を消す DB の操作と同じ取引の中で。
  アップロードの新しいキーは R2 に置く前に)。R2 から消せたら外し、消せなければ残ります。残った行は、同じ所有者の
  次の画像の操作(アップロード・外す・削除)で消し直します(積んでから 10 分以上たったもの・1回 20 件まで)。
  積んでいる数は API の応答(`data.cleanupPending`)に載り、匿名化したログにも出ます。
  ⚠ 消し直すまでの間は、キーを知っていれば配信の `/img` から取れます(キーは推測できない乱数)。
  ⚠ その所有者の画像の操作が二度と無ければ、消し直しも起きません(定期の掃除はまだありません)。
- 🔴 **画像型は、画像の読み込みが成功してから描きます**(`load` イベントを待つ。最大 8 秒)。
  **管理画面で画像を差し替え・削除した直後に、ちょうど設定を取得済みだった LP で発火すると**、
  古い画像キーのまま読み込みに失敗し、**そのページを再読み込みするまでポップが出ません**
  (新しい `/img/<key>` を取りに行く仕組みは無い=「出ないだけ」の fail-closed で、
  訪問者には壊れた画像リンクを見せません)。
- 🔴 **画像の読み込みの待ち時間(8秒)に外部根拠はありません**(実測に基づかない設計値)。
  画像の上限(2MB・GIF 3MB)を踏まえ、低速回線でも常識的な時間で決着する長さを狙ったものです。
